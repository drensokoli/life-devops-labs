WHY THIS FILE EXISTS
--------------------
The official ./verify.sh script contains a regex bug that causes checks 06 and
09 (the non-root USER checks for backend and frontend Dockerfiles) to always
fail, even when the Dockerfiles correctly contain the required USER instruction.

To get an accurate completion receipt, I ran a locally-patched copy named
verify-fixed.sh that fixes only this one bug. All other logic — check IDs,
output format, receipt path, dependency tree, scoring rules, etc. — is byte-
for-byte identical to the original.


THE BUG
-------
In ./verify.sh, lines 91–94:

    _dockerfile_has() {
      local file="$1" pattern="$2"
      grep -qiE "$pattern" "$file" 2>/dev/null
    }

This function is called by checks 06 and 09 with the pattern:

    '^USER[[:space:]]+(?!0|root)'

The construct `(?!0|root)` is a PERL-COMPATIBLE negative lookahead. POSIX
Extended Regular Expressions (which is what `grep -E` uses on GNU/Linux) do
NOT support lookaheads. As a result, `grep -E` cannot match this pattern
against ANY input, so the function always returns false.


PROOF (run inside WSL2 Ubuntu)
------------------------------
    $ echo "USER app" | grep -iE '^USER[[:space:]]+(?!0|root)'
    $ echo "exit=$?"
    exit=1

    $ echo "USER app" | grep -iP '^USER[[:space:]]+(?!0|root)'
    USER app
    $ echo "exit=$?"
    exit=0

    $ grep -iE '^USER[[:space:]]+(?!0|root)' backend/Dockerfile; echo "exit=$?"
    exit=1

    $ grep -iP '^USER[[:space:]]+(?!0|root)' backend/Dockerfile; echo "exit=$?"
    USER app
    exit=0

`grep -E` (POSIX Extended Regex) silently does not match.
`grep -P` (Perl-Compatible Regex) correctly matches `USER app`.


THE FIX
-------
In verify-fixed.sh, the SINGLE character change is:

    -  grep -qiE "$pattern" "$file" 2>/dev/null
    +  grep -qiP "$pattern" "$file" 2>/dev/null

That is the ONLY difference between verify.sh and verify-fixed.sh.

Both are placed in the final stage AFTER the runtime FROM statement, exactly

    > Final image must run as a non-root user (e.g. USER nextjs)
